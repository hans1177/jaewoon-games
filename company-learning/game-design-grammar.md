# 재운게임즈 기본설계 방법과 분류표

확정일: 2026-10-12. 오너가 확정한 기본설계 방법의 읽기용 설명이다.

이 문서는 게임 설계 참고 자료이며 독립적인 실행 정책이 아니다. 과거 중앙정책 참조는 삭제되었고 새 정책 권한을 이 문서에서 만들지 않는다.

## 적용 상태

기존 생성기·설계 스키마·심사기에 새 문법을 구현했다. 새 기본설계는 중앙 분류표를 직접 읽고 C 소재 두 개를 요구하지 않으며 D와 D 기반 @ 및 각 항목의 실패·취소·복구를 검수한다. 게임 코드·워크플로·저장·배포는 변경하지 않았다. 실제 게임 런타임 검증은 아직 확인하지 않았다. 이전 설계 점수는 새 문법 충족 증거가 아니다. 상위 정책의 기존 문법 필드는 실행 호환 기록이며, 새 문서상 설계 기준은 위 공식 정책 원본이다.

## 문법

**MAIN = A + B + C + D + @**

| 항목 | 선택 구성 | 역할 |
|---|---|---|
| A | 대표 게임 장르 시스템 + 소재 대분류 | 중심 플레이와 넓은 창작 범위 |
| B | 보조 세부 게임 장르 시스템 + 소재 중분류 | A를 보조하는 규칙·선택 |
| C | 소설·영화식 주 장르 + 보조 장르 | 작품의 성격·갈등·전개 |
| D | C의 두 장르 + 소재 소분류 | 구체적인 세계·존재·사건·규칙을 무한 창작 |
| @ | D에 근거한 파고들기 | 발견·재해석·숙련·새 선택을 무한 확장 |
| MAIN | 모든 요소가 연결된 결과 | 플레이어 역할·반복 목적·최종 게임 정체성 |

기존 게임을 기본설계할 때 B의 중심 시스템은 새 문법으로 생성하고 기존 게임 시스템은 **B 안의 보조 참조**로만 넣는다. 기존 게임 시스템으로 B의 중심 시스템을 대체하지 않는다. 기존 제목·세계관·소재·장르로 A·C·D·@를 고정하지 않는다. 과거 A 시스템 참고값도 새 문법에서는 B로 승계한다. 기존 게임 소스·저장·밸런스·서버 권한은 이 설계 입력 변경으로 수정하지 않는다.

A가 중심이고 B는 보조다. A+B를 동등한 두 중심 시스템으로 강제하지 않는다. A의 행동이 B의 조건을 바꾸고 B의 결과가 A의 다음 선택에 돌아오는 인과를 작성한다. C와 D는 추가 핵심 게임 시스템 축이 아니다.

## 게임 장르 분류표

A는 대표 장르를, B는 보조 세부 장르를 선택한다. B는 A와 다른 대표 장르 아래에서도 고를 수 있다. 예: A 역할수행 + B 타워 디펜스. 채집·제작·공격·회피는 내부 기능이며 대표 장르를 대체하지 않는다.

## 창작 소재 대·중·소 분류표

게임 장르와 별도의 표다. 스포츠는 게임 장르와 창작 소재에 각각 존재할 수 있다. 소재의 대·중·소는 탐색 깊이를 뜻한다. B를 A와 같은 소재 계통에서 반드시 선택해야 하는 제한은 없다. 다른 계통이면 각 분류 경로와 연결 이유를 작성한다.

소분류 예시는 각 행의 모든 중분류에 동시에 속하는 목록이 아니다. 실제 선택에는 정확한 분류 경로를 남긴다. 예: 신화→한국 신화→망자 명부, 전쟁·군사→보급전→보급로, 스포츠→야구→도루.

이 표는 확장 가능한 초기 분류 기준이다. 후보 총개수에 상한을 두지 않는다. 고정 후보를 문장 틀에 삽입한 것만으로 창작 완료를 주장하지 않는다. 집단 신뢰 같은 개념은 구체적인 대상·관계·규칙으로 발전시키고, 복선·반전 같은 서사 기법은 소재와 구분한다.

## 역사 소재 확장

역사 중분류는 **지역·문화권 × 시대·문명 × 역사 분야**로 좁힌다. 실제 성립하는 관계만 역사 사실로 연결한다.

| 선택 축 | 선택지 |
|---|---|
| 지역·문화권 | 한국 · 동아시아 · 유럽 · 서아시아 · 아프리카 · 남아시아 · 동남아시아 · 아메리카 |
| 시대·문명 | 고조선 · 삼국 · 발해 · 고려 · 조선 · 개항기 · 중국 왕조 · 일본 전국시대 · 몽골 제국 · 그리스·로마 · 중세 · 르네상스 · 대항해시대 · 산업혁명 · 메소포타미아 · 페르시아 · 이슬람 문명 · 오스만 제국 · 말리 제국 · 인더스 문명 · 마우리아 제국 · 무굴 제국 · 크메르 제국 · 마야 · 아즈텍 · 잉카 |
| 역사 분야 | 정치사 · 전쟁사 · 교역사 · 항해사 · 도시사 · 생활사 · 기술사 · 의학사 · 법제사 · 이주사 |

예: 역사→조선 교역사→보부상·장시·객주. 전쟁·군사를 소재 대분류로 선택하거나 역사 분야로 전쟁사를 탐색할 수 있다. 출처 경로로 분류 중첩을 구분한다.

## C 작품 장르

미스터리 · 코미디 · 공포 · 스릴러 · 판타지 · 공상과학 · 모험 · 드라마 · 로맨스 · 비극 · 풍자 · 무협

소설·영화식 작품 장르의 초기 선택 예시다. 주 장르 하나와 보조 장르 하나를 고른다. 예: 미스터리+코미디. 역할수행+타워 디펜스 같은 게임 장르 조합을 C에 다시 넣지 않는다. 보조 작품 장르가 사건·정보·갈등·선택을 어떻게 바꾸는지 작성한다.

## 기본 플로어 안의 설계 방법

기존 기본 플로어의 기본설계 단계에서 다음 과정을 수행하도록 정의한다. 별도 단계·큐·워크플로를 추가하는 설계가 아니며 현재 실행 순서를 바꾸지 않는다. 기존 기본설계 함수 내부에서 분류·창작·발견·육하원칙 심사를 수행한다.

**분류 선택 → 창작 후보 비교 → 반복 플레이 구체화 → 육하원칙·인과·모순 검수 → 상세설계 인계**

1. 분류 이름을 결과로 제출하지 않고 소재의 핵심 특징을 플레이 규칙으로 변환한다.
2. 소재의 원리를 이전·역전·대가·상속·숨김·재해석해 서로 다른 창작 후보를 만든다.
3. 후보를 중심 플레이 적합성·보조 역할·인과·의외성·구현 가능성으로 비교한다.
4. 한 장면 퀘스트가 아닌 반복 플레이·지역·인물·경제·성장에 지속되는 정체성 규칙을 선택한다.
5. 자체 검토에서 추상적인 부분은 해당 항목을 다시 구체화하고 기존 흐름으로 상세설계에 전달한다.

## 기본설계 작성 순서

1. A의 대표 게임 장르·핵심 시스템·소재 대분류를 선택한다.
2. B의 보조 세부 게임 장르·핵심 시스템·소재 중분류와 보조 역할을 선택한다.
3. A의 행동이 B의 조건을 바꾸고 B의 결과가 A로 돌아오는 반복 흐름을 구체화한다.
4. C의 작품 주 장르와 보조 장르를 각각 선택하고 경험·정보·갈등·선택에 미치는 차이를 작성한다.
5. D에서 소분류 소재의 분류 경로를 기록하고 두 작품 장르와 결합해 구체적인 세계·사건·규칙을 창작한다.
6. @는 D를 근거로 단서→실험→발견→새 선택→다음 의문을 연결하고 반복 생성의 상한을 두지 않는다.
7. MAIN은 A 중심·B 보조·C·D·@가 결합된 최종 정체성으로 정리한다.
8. MAIN·A·B·C·각 D 창작·각 @ 사례에 육하원칙과 결과·실패·취소·복구를 작성한다.

## 소재 경로와 특징

대분류별 `specificMaterials`에 중분류·소분류 이름·핵심 특징·행동·조건·결과·위험을 함께 기록한다. 소분류 예시를 모든 중분류에 공통 적용하지 않는다. 넓은 지역의 신화를 단일 전승으로 취급하지 않고, 구체적인 공동체·인물·의례를 사용할 때 출처와 맥락을 추가 검증한다.

생성기는 대분류를 먼저 독립 선택해 항목이 많은 분야에 선택권이 몰리지 않게 한다. 실제 소분류 특징으로 D를 창작하고 @의 실험과 새 행동을 연결한다. 제목은 소재나 시스템 선택 근거로 사용하지 않는다. 소재 후보는 중앙 표에 추가할 수 있으며 고정 총개수나 공통 장치 문장으로 창작을 대체하지 않는다. 상세설계는 메인 정체성과 중심·보조 게임 장르를 이어받아 실제 배치·수치·코드 책임·검증 장면을 구체화한다.

|---|---|
| 누가 | 실제 행동 주체·역할·관계·선택 책임 |
| 언제 | 실행 시점과 명확한 선행조건 |
| 어디서 | 구체적인 장소와 접근·이동·복귀 맥락 |
| 무엇을 | 대상·목표·플레이어 선택 |
| 어떻게 | 입력→판정→반응→상태 변화 |
| 왜 | 목적·욕망·갈등·원인과 다음 행동의 이유 |
| 결과 | 성공 출력·다음 선택·실패 및 취소 복구 |

추상적인 상태 변수나 복사 문장만 채우지 않는다. 구체적인 주체·장소·대상·행동·조건·반응을 적어 상세설계 담당자가 핵심 정체성을 새로 발명하지 않고 이어갈 수 있어야 한다. 상세설계에서는 맵 배치·이동 시간·외형·수치·소스 책임·검증 장면을 구체화한다.

## 설명 예시 — 포근섬

문법 이해용 새 예시이며 실제 적용 결과가 아니다.

- A: 시뮬레이션의 마을 건설·운영 시스템 + 신화 대분류.
- B: 보조 협력 퍼즐 시스템 + 한국 신화 중분류.
- C: 미스터리 + 코미디.
- D: 망자 명부 소분류. 명부가 뒤섞여 산 사람과 망자가 함께 정착한 섬을 창작한다. 명부 정정은 거주 권한·시설 이용·통행 규칙을 바꾸고 건설·운영 선택에 돌아온다.
- @: 명부 오류→이름 대여→중복 신분→섬의 등록 비밀을 파고든다. 단서·실험·실패 복구·새 운영 선택을 설계한다. 최초 사례 최소 4개는 출발점이며 상한이 아니다.
- MAIN: 산 사람과 망자가 함께 마을을 운영하며 잘못된 명부의 비밀을 풀어가는 게임. 마을 운영이 중심이고 협력 퍼즐은 보조한다.

## 문서와 실행 검증의 경계

생성기·스키마·심사기 코드 적용과 실제 게임 런타임 검증을 구분한다. 기존 Vibe2/Vibe3 및 F0~F9 정식 흐름 안에서 기존 책임 함수·설계 필드·심사기를 수정하고 새 설계와 런타임 증거로 검증해야 한다. 새 큐·워크플로·래퍼·우회 구조를 만들지 않는다. 이번 변경은 게임·저장·보상·밸런스·서버 권한을 바꾸거나 설계·게임·배포를 통과 처리하지 않는다.

## 파고들기: 장르별 콘텐츠 깊이

**파고들기의 주된 목적은 씨·디에 연관된 콘텐츠를 깊이 파고들어 연구하고, 그 연구를 바탕으로 새로운 콘텐츠를 창작·개발하는 것이다.**

관찰·가설·실험·발견·숙련·조합·재해석·재방문은 그 목적을 위한 과정이다. 연구 과정과 결과 자체를 중심·보조 게임 장르에 맞는 복합 콘텐츠로 구성한다. 연구 결과는 새로운 행동·관계·현상·존재·장소·사건·문화·규칙·조합으로 이어지고, 다시 다음 연구와 콘텐츠 개발의 대상이 된다. 연구 버튼·수치 상승·기능 해금만으로 목적을 충족했다고 인정하지 않는다.

@는 C의 작품 주·보조 장르와 D의 창작 세계·존재·장소·사건·문화·규칙에서 나온 연관 콘텐츠를 A의 중심 게임 장르와 B의 보조 세부 게임 장르에 복합적으로 연결해 새로 창작한다.

단서는 이야기의 단서뿐 아니라 적 패턴·현상·입력 반응·배치·자원 흐름·상호작용의 차이도 포함한다.

실험은 전투·조작·배치·제작·운영·조합 등 해당 장르의 실제 플레이로 구성한다.

단서→실험→발견→새 선택→다음 의문은 플레이의 인과 연결이다. 모든 사례를 조사 퀘스트·기록 장치·경로 해금으로 만들지 않는다.

각 사례에 D 출처, 관찰한 차이, 실제 입력과 조건, 성공·실패·취소·복구, 달라지는 행동과 결과를 작성한다.

초기 서로 다른 사례 최소 4개는 출발점이며 총개수 상한은 없다. 이름·번호·수치만 바꾼 반복은 새 사례가 아니다.

장르별 예시는 탐색 범위이며 고정 창작 답안·필수 기능 목록·장르별 고정 결과로 사용하지 않는다.

기본설계는 표준 문법의 A·B·C·D·@를 연결해 MAIN을 도출한다. 확정한 MAIN과 중심·보조 장르에 맞춰 상세설계를 작성하며 기존 게임 제목·내용을 새 정체성의 기준으로 삼지 않는다.

| 장르 | 탐색할 콘텐츠 요소 예시 |
|---|---|
| 액션·슈팅 | 적 패턴·타이밍·약점, 무기 운용·연계·대응 |
| 역할수행 | 빌드·장비 조합, 인물 관계·선택의 후속 결과 |
| 어드벤처 | 숨은 장소·사건 재해석, 복수 해결법·재방문 변화 |
| 전략 | 배치·상성·자원 운용, 기만·상대 전술 대응 |
| 시뮬레이션 | 생산 연결·시설·동선, 주민 행동·운영 최적화 |
| 생존 | 생태 관계·제작 조합, 위험 활용·거점·탐험 전략 |
| 퍼즐 | 규칙 조합·숨은 조건, 복수 해법·고급 응용 |
| 스포츠·레이싱 | 기술 숙련·코스 공략, 상대 읽기·팀·장비 전략 |
| 리듬 | 박자 해석·입력 기술, 패턴 숙련·표현·변주 |
| 카드·보드 | 덱·말 조합·수 읽기, 연계·상대 전략 역이용 |
| 파티 | 역할 조합·협동 방식, 심리전·라운드별 대응 |
| 방치·증분 | 투자 순서·생산 조합, 자동화·성장 전환 전략 |

이 절은 문법과 검수 기준의 문서 수정이다. 생성기·디자이너 작성 기능·상세설계 인계·게임 구현·실행·배포 완료를 뜻하지 않는다.

## 씨·디 연관 콘텐츠의 복합 창작

파고들기는 씨의 작품 주·보조 장르와 디의 구체 창작에서 나온 연관 콘텐츠를 에이의 중심 게임 장르와 비의 보조 세부 게임 장르에 복합적으로 연결해 새로 창작하는 과정이다.

씨가 만드는 갈등·경험·정보·해석과 디의 존재·장소·사건·문화·규칙이 결합해 새로운 행동·관계·현상·조합·사건·결과를 만든다. 그 결과는 다시 씨·디와 에이·비의 다음 선택을 바꾸며 파고들기를 이어 간다.

약점·빌드·생산·숨은 장소 같은 장르별 항목은 가능한 표현 수단이다. 목록을 채우거나 여러 기능을 단순 병렬 배치한 결과를 창작 완료로 인정하지 않는다. 각 사례는 씨·디의 어떤 관계에서 파생됐는지, 중심·보조 게임 장르가 실제 플레이에서 어떻게 결합되는지, 이전 사례와 어떤 행동·조건·결과가 달라졌는지를 작성한다.

단서→실험→발견→새 선택→다음 의문, 육하원칙과 성공·실패·취소·복구, 초기 서로 다른 사례 최소 4개와 확장 상한 없음은 유지한다. 고정된 창작 답안이나 필수 기능 목록을 강제하지 않는다.


## 상세설계와 기존 제작 흐름 작업 계획

작성일: 2026-10-13. 기본설계 원본과 기존 실행 순서를 유지하고, 기존 제작 계획·작업 지시·검증 함수에 직접 반영한다.

### 목적과 범위
- 각 게임의 확정된 MAIN/A/B/C/D/@를 상세 구현 명세로 이어 준다. 같은 장르라도 게임별 행동·상태·서사·소재를 복사하지 않는다.
- 기존 게임은 B 보조 참조로만 사용한다. 장르 프로필은 검토 관점이며 승인되지 않은 시스템 추가 권한이 아니다.
- 상세 명세에는 첫 플레이·튜토리얼, 시스템 연결, 세계·바이옴, 인물·행동, 이야기, 모션·연출·소리·카메라, 인터페이스, 자산·원본 책임, 검증 시나리오를 포함한다.
- 상세 정보가 없으면 누락으로 기록하고 기존 설계·구현 경로에서 구체화한다. 이름 일치나 설명 추가만으로 구현·실행 완료를 주장하지 않는다.

### 기존 책임 함수에서 구현
1. `tools/company-build-up-directive.mjs#extractDesignContext`: 작성된 상세설계·튜토리얼·연출·인터페이스·검증 명세를 작업 지시까지 보존한다.
2. `tools/company-roblox-production-plan.mjs#buildRobloxProductionPlan`: 같은 제작 계획에 게임별 상세 요구와 필요한 기존 도구·검증 방법을 연결한다. 가·나 복합 시스템을 한 장르 기본 기능 묶음으로 대체하지 않는다.
3. `buildInterfaceBlueprintContract/validateInterfaceBlueprint`: 기존 화면 도안에서 튜토리얼·연출의 진입·행동·성공·실패·취소·복구와 상태별 화면 검증 시나리오를 소스에 연결한다. 정적 검사는 실제 실행 증거가 아니다.
4. 기존 소스 작업자와 변경 검증이 같은 도안·명세를 전달·검사하도록 유지한다. 새로운 큐·워크플로·래퍼·병렬 설계 시스템을 만들지 않는다.
5. 기존 F9 검수·서버 배포 경로에서 검증된 매 주기 결과를 로블록스 서버에 배포한다. 로비 완성이나 공개 판정을 서버 배포 조건으로 혼용하지 않는다. 정확한 F9·소스·자산·빌드 식별은 유지한다.
6. 공개 여부는 오너가 결정한다. 기존 공개 상태를 자동 변경하지 않으며, 배포 실패는 해당 주기 식별을 보존해 기존 복구 경로로 재시도한다.

### 검증 방법
각 적용 요구에는 진입 조건, 실제 입력 순서, 기대 상태와 화면 결과, 실패·취소·재시도, 책임 소스, 실행 증거를 연결한다.
- 인터페이스: 실제 버튼·터치·스크롤·뒤로/닫기, 선택·잠금·빈 목록·로딩·오류·성공·실패, 거래·보상 중복 방지.
- 튜토리얼: 새 저장 상태의 첫 행동·학습 결과·정체 힌트, 설계된 건너뛰기·재시작·재접속 복구.
- 연출: 시작·종료·중단 조건, 카메라·모션·효과·음향 시점, 입력 복구, 모바일 가독성·성능.
- 세계: 지면·시작 위치·경로·건물 출입·설계된 배치와 시야를 상태 및 화면 증거로 확인.
- 기능·저장·서버 권한: 정상·실패·연속 입력·저장/재접속과 영향 범위 회귀 검수.
- 멀티: 기존 중앙 정책의 단계별 적용·증거 방식을 유지한다. 새 중복 게이트를 만들지 않는다.
- 자산: 등록부 버전·선택·원본 해시·게임 소스·빌드·실행 증거 식별을 대조한다.
- 플로어: F0 소스, F1 시작, F2 월드, F3 캐릭터, F4 물리·이동, F5 입력·카메라·화면, F6 통신·저장·상태, F7 기존 멀티 계약, F8 게임별 플레이, F9 증거 통합·회귀.
- 배포: F9 통과한 동일 주기 결과의 서버 배포 버전과 식별을 기록한다. 배포·공개·실제 플레이 통과를 구분한다.

코드 검사, 서버 실행, 게임별 실제 설계 일치, 서버 배포를 각각 보고한다. 확인되지 않은 단계는 미검증으로 남긴다.

### 게임별 컨셉 스타일 추가 범위
재질 25분류와 색·표면 변형 100개를 스타일 100종으로 집계하지 않는다. 공용 나무·몬스터·건물 원본은 보존하고 검증된 동일 게임 설계의 스타일 명세를 기존 자산 제작 계획에 우선 적용한다. 실루엣·비율·재질 반응·표면·팔레트·조명·모션·화면 언어를 게임별 파생으로 연결하고 같은 빌드의 화면·상태·성능으로 검증한다. 오래된 다른 스타일 공유 문서는 새 설계를 덮지 못한다. 색 변경이나 계획 생성만으로 스타일 적용 완료를 주장하지 않는다.



### 기존 게임 자산·로비 전면 품질 재검토
- 기존 자산 연결 이력은 품질 면제 근거가 아니다. 캐릭터·몬스터·건물·가구·식생·음원·인터페이스를 게임별 설계·화면 기준으로 다시 검토하고 부족한 표현을 교체한다.
- 품질 좋은 범용 원본을 우선 재사용·변형·재조합한다. 원본은 보존하고 로블록스 메시·리그·재질·모션·음원 설정과 업로드 식별을 별도 파생본으로 관리한다.
- 기존 로비는 같은 게임의 진입·파티·상점·포탈 기능을 보존하면서 컨셉·동선·시야·조명·배경을 새로 구성한다. 로비 없는 게임에 로비를 강제하지 않는다.
- 기존 `buildVisualDirective`와 자산 제작·소스 작업자가 같은 요청을 소비한다. 새로운 제작 큐·래퍼·우회 배포는 만들지 않는다.
- 컴파일·구조 검사는 실제 화면 품질·모바일 실행·업로드 성공을 대신하지 않는다. 검증된 정확한 F9 버전만 기존 서버 배포 경로로 이어 간다.

기계판독 기준은 `company-asset-library.json`과 `assets/vibe-studio-asset-universe.js`가 담당한다.

## 공통 원칙

1. 기존 게임자산과 회사 공통자산을 새 제작보다 먼저 찾는다.
2. 좋은 기존자산은 바로 폐기하지 않고 그대로 사용, 가벼운 테마변형, 스타일변형, 파츠재조합, 네이티브 재저작 베이스, 현재자산 유지·개선 중 하나로 처리한다.
3. 내부점수는 사용 허가 점수가 아니다. 낮은 점수 자산도 안전하고 호환되면 사용할 수 있다.
4. 더 좋은 호환자산은 유효품질과 게임 정체성을 비교해 교체한다.
5. 공통자산은 표현을 담당하고 게임 규칙을 소유하지 않는다.
6. 외부 고급게임은 정보구조, 시각위계, 탐색깊이, 상태표현, 접근성, 입력전환, 화면전환, 시스템 연결원리만 참고한다.
7. 특정 게임의 고유 UI, 수치, 레이아웃, 규칙, 아트디자인을 복제하지 않는다.
8. 모바일 터치, 키보드/마우스, 게임패드를 같은 정보구조에서 지원한다.
9. 상태는 색상만으로 구분하지 않는다.
10. 하나의 자산 DNA가 가능한 경우 월드모델, 드랍모델, 인벤토리, 제작, 상점, 도감 표현에 이어진다.

## 내부자산 정례 감사

새 스케줄러를 만들지 않는다.
아래 사건이 발생할 때 기존 자산 책임영역에서 감사를 수행한다.

### 항상
- 내부자산 추가
- 내부자산 수정
- 공통팩 버전 상승
- 새 장르 요구 추가
- 새 게임의 자산 요구가 기존 장르 매트릭스에 없는 경우

### 바인딩 전
- 기존 게임자산 검색
- 회사 공통자산 검색
- 교차팩 커버리지 계산
- 현재 게임에 필요한 장르 매트릭스 비교
- 중복 제작 후보 제거
- 안전/라이선스/플랫폼/역할 호환성 확인

### 바인딩 후
- 실제 사용 파일 기록
- 파생/변형 계보 기록
- 생산 검증과 내부 품질점수 분리
- 실패 이력은 사용금지 대신 유효품질 감점으로 반영
- 더 좋은 호환자산 발생 시 교체 후보화

### 공통팩 개정
- 해당 팩만 보는 감사와 회사 전체 교차팩 감사를 둘 다 수행
- 다른 팩이 이미 가진 구성은 새 결손으로 중복 제작하지 않는다
- 실제 회사 전체 결손만 다음 제작 우선순위로 남긴다

## 완료 기준

문서만 추가했다고 완료가 아니다.

내부자산 변경은 최소한:
- 카탈로그 반영
- 회사 라이브러리 등록
- 기계판독 메타 반영
- 기존 권한 보존
- 자산 QA
- 회귀검증
- 최신 main freshness 확인
- main 반영

까지 확인되어야 완료로 본다.

Studio/native runtime 검증이 없는 자산은 productionVerified로 승격하지 않는다.

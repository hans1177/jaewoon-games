# 대충알피지 — 로블록스 문명 서바이벌 액션 RPG 개발 기준서

> 게임 제목: **대충알피지** (출시 표시명). 내부 게임 식별자: `simple-rpg` (변경 금지).  
> 대상: Roblox Studio / Luau / Rojo / GitHub, 사용자 명시 스크립트를 기능 요구 기준으로 보존.  
> 기준 저장소: `hans1177/jaewoon-games`, `main`; 수정은 기존 게임의 `shared/`, `server/`, `client/`, `default.project.json` 책임 구조를 사용한다.  
> **이 문서는 구현 요구 명세다. 실제 실행·QA·배포 완료 증거를 대신하지 않는다.**

## 1. 게임 비전
- 발하임(Valheim)식 로우폴리 판타지 자연/고대 유적 표현, 그라운디드(Grounded)식 액션 타이밍을 *참고*하되 외부 게임의 보호되는 리소스/캐릭터/코드/인터페이스는 복제하지 않는다.
- 로블록스 R15 블록키 캐릭터, 핸드페인팅 분위기의 무광 질감 및 약한 표면 노이즈.
- 작은 모험이 성립하는 첫 플레이: 문명 선택 → 필드 이동 → 채집 → 몬스터 전투/패링/회피 → 연구 해금 → 성장 → 다음 지역.
- 24개 고대 문명 고유 지역/특성/랜드마크, 5시대 72연구, 생존/제작/성장, 자율 문명 발전.

## 2. 비주얼 및 카메라
- Roblox의 Future에 해당하는 현재 조명 설정: `LightingStyle=Realistic`, `PrioritizeLightingQuality=true`. 지역 분위기에 맞는 `Atmosphere` 밀도/안개·유적·로우폴리 숲.
- 낮은 채도의 나무·가죽·암석·양피지, 모바일 성능에 맞춘 이펙트 및 월드 크기.
- 0.25초 퍼펙트 패링 성공 시 반짝이는 스파크/짧은 카메라 흔들림/0.05초 히트스탑/적 스턴 연출.
- 원본에 포함된 비주얼 URL은 `raw.githubusercontent.com/placeholder/...`인 *플레이스홀더*이므로 실제 원본 컨셉 이미지가 아니다.

## 3. 조작/전투
- 공격: 서버 측 거리/방향/대상 생존 상태/연타 제한 검사.
- 방어/정밀 패링: 서버 시계 기반 0.25초 기본 성공 구간; 개별 문명 패링 보정은 기존 데이터 우선. 성공 시 적 스턴/연구 보상은 기존 수치 보존.
- 회피: 서버 이동 가능 지면 검사 및 기존 무적 판정 유지.
- 전투 예고→패링/회피→적 스턴/처치→전리품·연구→성장으로 연결. 모바일 터치, 데스크톱 키보드, 게임패드 입력 검증.

## 4. UI/UX
- 원목 판자/가죽 테두리/양피지 표현; 9-Slice 적용 가능한 원본 에셋 확보 시 바인딩한다.
- 상단 HUD: 실제 플레이어 체력/스태미나, 문명·시대·자원 상태; 미니맵은 현재 좌표/문명 지역/타 플레이어를 판별 가능한 형태로 표현.
- 1~8 퀵슬롯 아이템 및 행동 단축키; 모바일 터치 안전 영역 보장.
- 인벤토리 4열×8행 32칸, 착용 장비 확인, 제작 가능 목록과 자원 부족 이유.
- 5개 시대 72개 연구 노드 연결, 선행 조건 표시, 유레카 달성 시 황금빛 이펙트.
- 모바일 버튼, 스크롤, 화면 잘림, 로딩, 패널 닫기, 재접속 점검.

## 5. 데이터/구성
- `shared/RaceData.luau`: 24개 문명 정의 및 고유 지역/랜드마크/수치.
- `shared/TechTreeData.luau`: 5개 시대/72개 연구, 유레카, 선행 조건.
- `shared/GameConfig.luau`: 게임 명칭/기본값/기존 저장 필드, 전투·월드 상수.
- `server/Game.server.luau`: 게임 서버 권한 전투·채집·연구·지역·스폰·적 AI·저장/복구·원격 입력 검증.
- `client/Game.client.luau`: 액션 입력·카메라·HUD·문명 선택·기술 연구·인벤토리.
- `default.project.json`: 기존 Rojo 연결 유지.
- 사용자 예시의 `src/ReplicatedStorage/Modules/...`은 논리적 책임 구분 참조이며 **실제 저장소 기존 책임 경로를 우선**한다. 중복 스크립트/그림자 파이프라인 추가 금지.

## 6. 필수 보안과 데이터 보존

## 10. 직접 게임 개발·자가 수정·자동 배포 실행 지시 (2026-10-15)

**직접 책임:** 이 계획서는 단순 문서 작성 요청이 아니다. ChatGPT 개발 담당자는 실제 \`roblox-games/simple-rpg/\` 게임의 책임 소스(shared/server/client/default.project.json)를 직접 읽고 수정·커밋한 뒤 변경된 기능을 기존 CI와 Roblox 개발 플로우에 연결한다. 완료 주장은 실제 커밋·검증·게시 증거를 갖춘 경우에만 한다. 사용자 명칭 **대충알피지**와 내부 ID \`simple-rpg\`, 기존 DataStore 키 및 보상 밸런스는 보존한다.

### 3가지 실행 아이디어
1. **GitHub App + Roblox Open Cloud:** 이 저장소에는 이미 Roblox F0~F9 자동 개발·검증·정본 게시 파이프라인과 \`.github/workflows/company-roblox-source-drift-sync.yml\`이 있다. 새 \`deploy.yml\`로 무조건 즉시 게시하는 중복 경로를 만들지 않는다. 기존 검증이 성공한 빌드와 게임별 승인된 Universe/Place에만 기존 게시 단계가 자동 이어지게 한다. Open Cloud 키는 GitHub Actions Secret \`ROBLOX_OPEN_CLOUD_API_KEY\` 등 기존 코드가 참조하는 키를 사용하고, 키 원문은 GitHub나 문서에 절대 기록하지 않는다. 예제의 \`ROBLOX_OPEN_CLOUD_KEY\` 등은 실제 저장소 계약과 확인 후 맞춘다.
2. **코드 작성·자가 수정 루프:** 신규 Luau 모듈은 \`--!strict\`와 명시적 Player/Boolean/반환 타입을 기본으로 한다. 클라이언트 입력은 서버에서 자료형·거리·소유권·속도를 검증한다. 추가 코드가 다른 모듈에 순환 의존하지 않는지 검사한다. CI의 \`qa/simple-rpg-ai-authoring.test.mjs\`는 정적·연결·기존 책임 경계 회귀 검사이며 실제 Luau 타입 검사/엔진 실기기 테스트와 동일하지 않다. 기존 레거시 스크립트 전체에 \`--!strict\`를 무작정 붙이지 않는다.
3. **모바일 단축 명령:** "버그 수정 1번 시나리오" = AI 동료 소환→따라오기→전투/채집→해산 시나리오 확인 및 책임 소스 수정. "동료 AI 고쳐" = \`server/CompanionAI.luau\`, \`server/Game.server.luau\`, \`client/Game.client.luau\` 확인. "패링 수정" = 기존 \`civGuard\`/적 공격 판정·클라이언트 연출 확인. "자동 배포 상태" = 소스 리비전·F0~F9 파이프라인·승인된 Place 게시 기록을 읽어 실제 상태 보고. 메시지 길이와 무관하게 파일을 추측 생성하지 말고 책임 경로부터 확인한다.

### 오너 최신 자동승인 및 배포 지시
- 오너는 **전체 게임 자동 승인 및 플로우에 따른 자동 배포**를 원한다. 별도의 인간 클릭 승인·같은 검증을 배포 단계에서 다시 반복하지 않는다.
- **기존 플로우의 앞 단계 통과 증거를 재사용**하여 정본 게시 단계까지 연속으로 진행한다. 게임별 대상 매핑/인증 정보가 없거나, 앞 단계 PASS 및 실제 게시 증거가 없다면 자동 배포 **완료라고 허위 보고하지 않는다**. 중앙 실행 정책·보안 게이트를 무시하는 강제 게시 경로는 이 게임 문서에서 새로 만들지 않는다.
- 직접 개발 완료와 실제 Roblox 라이브 게시 완료는 별개 상태로 기록한다. 모든 게임 자동화 범위는 플랫폼 전역 권한/파이프라인으로 구현해야 하며, 대충알피지 문서만으로 다른 게임의 자동 게시가 활성화된 것으로 간주하지 않는다.

## 11. 1~3시대 자원→몹→아이템→유레카→종족 건축 인과관계 (2026-10-15 오너 요구)

### 비주얼·조작 기준
- R15 블록키+무광 손그림 텍스처, Future Lighting, 회청색 Atmosphere 안개, 고대 유적과 로우폴리 숲.
- 퍼펙트 패링 0.25초, Camera Shake, 0.05초 히트스탑과 Stunned 연출.
- 원목·가죽·파피루스 9-Slice, 체력/스태미나, 1~8 퀵슬롯, 미니맵; 4×8 인벤토리·장비/제작 목록, 5시대 72기술 지도와 황금 유레카 이펙트.
- 이 요구들은 기존 계획대로 유지되며 여기 기록되었다고 실제 실행이 검증된 것은 아니다.

### 시대별 원본 인과관계
**석기:** Wood ×10 + Stone ×10 → 돌창(StoneSpear) → 야생 멧돼지(WildBoar) → 가죽(Hide) → '야생 몹 1마리 사냥' 유레카 / 관련 연구 비용 50% 할인 → 석제 성벽 + 고조선 단군 제단(테크 비용 추가 15% 할인).

**청동기:** CopperOre ×15 + TinOre ×15 → 용광로 청동 주괴(BronzeIngot ×5) → 청동검(BronzeSword) → 청동 골렘(BronzeGolem) → 코어 크리스탈(CoreCrystal) → '청동 주괴 5개 제련' 유레카 / 관련 연구 비용 50% 할인 → 이집트 피라미드(건축 액션 대기시간 20% 감소).

**철기:** IronOre ×20 + Coal ×20 → 고로 철 주괴(IronIngot ×5) → 철제 대검(IronGreatsword) → 암흑 철기 기사(IronKnight) → 다크 아이언(DarkIron) → '기사 몹 격파' 유레카 / 관련 연구 비용 50% 할인 → 로마 콜로세움(방어력 +15%)·바이킹 드라카르 조선소.

### 내가 직접 수정하는 실제 책임 경로
- shared/ProgressionData.luau: 상호 의존 없는 재료·레시피·무기·종족 건축 상수.
- shared/GameConfig.luau: 기존 DataStore 키 변경 없이 장비·드롭·건축·유레카 저장 필드 호환 확장.
- server/Game.server.luau: 자원·생산 시설·특수 몹 생성, 서버 거리·쿨다운·보상 판정, 자원 차감/드롭/건축과 재접속 상태 복원.
- client/Game.client.luau: 모바일 제작·장비·건축 화면, V/B 단축키 및 실제 서버 이벤트 연결.
- qa/simple-rpg-age-chain.test.mjs: 저장 호환과 원격/재화/연구 로직을 기존 QA에 연결.

### 기존 72개 연구와 시대 번호의 차이
오너의 새 요구는 1=석기·2=청동기·3=철기인데 기존 TechTreeData는 신화(1~14), 석기(15~28), 청동기(29~44), 철기(45~60), 영웅(61~72) 순이다. 기존 세이브·선행연구를 손상하지 않기 위해 **이번 코드의 전용 유레카 50% 할인은 실제 연구 ID 15·29·45**에 연결했다. 사용자 원문의 테크 1·2·3과 완전히 같은 기술 재편은 미완료로 표시한다.

### 구현 경계
- 원문에 없는 건축 비용·기본 무기 피해·몬스터 체력·건축 대기시간은 현행 플레이 테스트를 위한 초깃값이고 원문에서 확정한 수치가 아니다.
- 4~5시대 상세 인과관계는 아직 제공되지 않았다. 200개 스크립트를 제작·검증했다거나 실제 Roblox 게시까지 완료했다고 표기하지 않는다.
- 배포 단계에서 중복 검증을 추가하지 않으며 기존 F0~F9 자동 정본 플로우를 이용한다.

## 12. 통신/동기화 마스터 스크립트 통합 (2026-10-15)

### 단일 실행 경로
- 사용자 예시의 `ReplicatedStorage/Modules`, `ServerScriptService/Systems/TechTreeServer.server.luau`는 개념상의 폴더 구조다. 이 게임에는 **기존 단일 서버** `server/Game.server.luau`와 **기존 단일 클라이언트** `client/Game.client.luau`가 있으므로 별도 경쟁 서버/인벤토리 스크립트를 추가하지 않는다.
- 서버는 시작할 때 `ReplicatedStorage/Remotes` 폴더와 원격 5개를 생성/검증한다. 기존 `Config.RemoteName` 일반 액션 이벤트와 `ReplicatedStorage/Shared`의 데이터 모듈을 계속 사용한다.
- `shared/TechTreeData.luau`의 기술 스키마는 `TechID`, `Prerequisite`, `RequiredResources`, `Era`이다. `shared/TypeDefinitions.luau`(v2.1 계약 참조)를 근거로 스키마 또는 저장 필드를 강제 마이그레이션하지 않는다.

| 원격 | 방향 | 단일 처리 책임 | 반영 |
| --- | --- | --- | --- |
| `ParryEvent` | 클라이언트 → 서버 | 기존 `civGuard` 및 서버 패링 창/쿨다운 | 패링 액션·결과는 기존 서버 이벤트/속성 활용 |
| `DodgeEvent` | 클라이언트 → 서버 | 기존 `civDodge`의 생존/지면/쿨다운 검증 | 실제 회피/카운터 |
| `UnlockTechRequest` | 클라이언트 → 서버 → 클라이언트 | `civResearch(player, techID)`: 유효 ID, 다음 연구, 문명, 선행 조건, 유레카, 자원, 쿨다운 | 실제 비용 차감·해금 후 `(true, message)`; 실패 시 `(false, message)` |

### 보존/보안
- 기존 액션 ID `CivResearch`도 **동일** `civResearch`를 사용한다. 클라이언트가 전송한 임의 재고·연구 성공·피해량은 받아들이지 않는다.
- `CivReady` 전 연구·패링·회피를 거부한다. 기술 번호는 정수 1~72 및 **다음 순차 연구**만 허용한다. 연구 자원은 오직 서버에서 차감한다. 원격 성공만으로 연구가 되었다고 말하지 않는다.
- `SyncInventoryEvent`는 **클라이언트 → 서버 입력을 제공하지 않는** 단방향 복제이며 해당 플레이어에게만 전송한다. 서버의 숫자 어트리뷰트가 정본이다.
- DataStore `simple-rpg-development-v1`, 저장 레코드의 `player:<UserId>` 형식, 숫자 키/기존 보상·전투 수치는 보존한다. 저장은 기존 `UpdateAsync`/주기 저장/퇴장 저장에 맡기며 연구 때마다 별도 저장소에 중복 저장하지 않는다.
- 기존 대형 서버/클라이언트는 레거시 타입 불명 부분이 있으므로 파일 전체에 `--!strict`를 일괄 적용하지 않았다. 모든 신규 원격 판정은 기존 서버 검증 로직에 연결한다.

### 검증 및 출하 체크
1. 소스 정적 확인: 원격 생성, 연구 리턴의 실제 판정 연계, 구형 액션 유지, 스냅샷 단방향, 저장 원본 유지 — **15/15 항목 확인**.
2. 자동 테스트 코드: `qa/simple-rpg-ai-authoring.test.mjs`에 통신 권한/클라이언트 갱신 회귀 항목 추가. 이 추가 자체는 CI PASS 증거가 아니다.
3. 아직 필요한 엔진 검증: 진입→문명 선택→패링/회피 서버 판정→연구 비용 부족/선행 실패/성공→가방 반영→나갔다 재접속 후 자원/기술 유지→모바일 조작.
4. **배포 상태: NOT_PUBLISHED.** 오너 직접 게시의 해당 게임 대상과 인증/빌드/런타임 증거가 없어 Roblox Place 배포 성공·버전 번호를 주장하지 않는다.

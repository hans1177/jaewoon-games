# 대충알피지 — 로블록스 문명 서바이벌 액션 RPG 개발 기준서

> 게임 제목/내부 브랜드: **대충알피지**. 기존 연동·저장 기술 키: `simple-rpg` (게임명 아님).  
> 대상: Roblox Studio / Luau / Rojo / GitHub, 사용자 명시 스크립트를 기능 요구 기준으로 보존.  
> 기준 저장소: `hans1177/jaewoon-games`, `main`; 수정은 기존 게임의 `shared/`, `server/`, `client/`, `default.project.json` 책임 구조를 사용한다.  
> **이 문서는 구현 요구 명세다. 실제 실행·QA·배포 완료 증거를 대신하지 않는다.**

## 1. 게임 비전
- 발하임(Valheim)식 로우폴리 판타지 자연/고대 유적 표현, 그라운디드(Grounded)식 액션 타이밍을 *참고*하되 외부 게임의 보호되는 리소스/캐릭터/코드/인터페이스는 복제하지 않는다.
- 로블록스 R15 블록키 캐릭터, 핸드페인팅 분위기의 무광 질감 및 약한 표면 노이즈.
- 작은 모험이 성립하는 첫 플레이: 문명 선택 → 필드 이동 → 채집 → 몬스터 전투/패링/회피 → 연구 해금 → 성장 → 다음 지역.
- 24개 고대 문명 고유 지역/특성/랜드마크, 5시대 72연구, 생존/제작/성장, 자율 문명 발전.

## 2. 비주얼 및 카메라
- Roblox의 Future에 해당하는 현재 조명 설정: `LightingStyle=Realistic`, `PrioritizeLightingQuality=true`. 지역 분위기에 맞는 `Atmosphere` 밀도/안개·유적·로우폴리 숲.
- 낮은 채도의 나무·가죽·암석·양피지, 모바일 성능에 맞춘 이펙트 및 월드 크기.
- **에셋 제작 원칙:** 이미 확보한 검증된 CC0 원본을 우선 재사용하고, 게임 스타일에 필요한 부분만 수정한다. 신규 제작 전면 금지가 아니며 적합한 원본이 없는 경우에 한해 부족한 부분을 신규 제작할 수 있다(26절).
- 0.25초 퍼펙트 패링 성공 시 반짝이는 스파크/짧은 카메라 흔들림/0.05초 히트스탑/적 스턴 연출.
- 원본에 포함된 비주얼 URL은 `raw.githubusercontent.com/placeholder/...`인 *플레이스홀더*이므로 실제 원본 컨셉 이미지가 아니다.

## 3. 조작/전투
- 공격: 서버 측 거리/방향/대상 생존 상태/연타 제한 검사.
- 방어/정밀 패링: 서버 시계 기반 0.25초 기본 성공 구간; 개별 문명 패링 보정은 기존 데이터 우선. 성공 시 적 스턴/연구 보상은 기존 수치 보존.
- 회피: 서버 이동 가능 지면 검사 및 기존 무적 판정 유지.
- 전투 예고→패링/회피→적 스턴/처치→전리품·연구→성장으로 연결. 모바일 터치, 데스크톱 키보드, 게임패드 입력 검증.

## 4. UI/UX
- 원목 판자/가죽 테두리/양피지 표현; 9-Slice 적용 가능한 원본 에셋 확보 시 바인딩한다.
- 상단 HUD: 실제 플레이어 체력/스태미나, 문명·시대·자원 상태; 미니맵은 현재 좌표/문명 지역/타 플레이어를 판별 가능한 형태로 표현.
- 1~8 퀵슬롯 아이템 및 행동 단축키; 모바일 터치 안전 영역 보장.
- 인벤토리 4열×8행 32칸, 착용 장비 확인, 제작 가능 목록과 자원 부족 이유.
- 5개 시대 72개 연구 노드 연결, 선행 조건 표시, 유레카 달성 시 황금빛 이펙트.
- 모바일 버튼, 스크롤, 화면 잘림, 로딩, 패널 닫기, 재접속 점검.

## 5. 데이터/구성
- `shared/RaceData.luau`: 24개 문명 정의 및 고유 지역/랜드마크/수치.
- `shared/TechTreeData.luau`: 5개 시대/72개 연구, 유레카, 선행 조건.
- `shared/GameConfig.luau`: 게임 명칭/기본값/기존 저장 필드, 전투·월드 상수.
- `server/Game.server.luau`: 게임 서버 권한 전투·채집·연구·지역·스폰·적 AI·저장/복구·원격 입력 검증.
- `client/Game.client.luau`: 액션 입력·카메라·HUD·문명 선택·기술 연구·인벤토리.
- `default.project.json`: 기존 Rojo 연결 유지.
- 사용자 예시의 `src/ReplicatedStorage/Modules/...`은 논리적 책임 구분 참조이며 **실제 저장소 기존 책임 경로를 우선**한다. 중복 스크립트/그림자 파이프라인 추가 금지.

## 6. 필수 보안과 데이터 보존

- 독립 QA/정적 검증/빌드·게임별 실제 게시 증거 없이는 배포·완료·PASS로 표시 금지.

## 8. 개발·배포 원칙
- 사용자 승인된 게임 제목 **대충알피지**를 로블록스 표시명에 사용한다. 내부 ID `simple-rpg`는 변경하지 않는다.
- 신규 문서 자체를 완료 증거로 취급하지 않는다. 파일 구현, 현재 `main`으로 검증된 병합, 현재 아티팩트 빌드, 실제 Roblox 대상 Place 버전 검증을 분리한다.
- 소유자 지시로 삭제된 과거 중앙정책 파일에는 의존하지 않는다. 현재 유지 중인 개발/QA/게시 체인과 전용 Roblox Place 및 저장 데이터 계약을 그대로 준수한다.

## 10. 직접 게임 개발·자가 수정·자동 배포 실행 지시 (2026-10-15)

**직접 책임:** 이 계획서는 단순 문서 작성 요청이 아니다. ChatGPT 개발 담당자는 실제 \`roblox-games/simple-rpg/\` 게임의 책임 소스(shared/server/client/default.project.json)를 직접 읽고 수정·커밋한 뒤 변경된 기능을 기존 CI와 Roblox 개발 플로우에 연결한다. 완료 주장은 실제 커밋·검증·게시 증거를 갖춘 경우에만 한다. 사용자 명칭 **대충알피지**와 내부 ID \`simple-rpg\`, 기존 DataStore 키 및 보상 밸런스는 보존한다.

### 3가지 실행 아이디어
1. **GitHub App + Roblox Open Cloud:** 이 저장소에는 이미 Roblox F0~F9 자동 개발·검증·정본 게시 파이프라인과 \`.github/workflows/company-roblox-source-drift-sync.yml\`이 있다. 새 \`deploy.yml\`로 무조건 즉시 게시하는 중복 경로를 만들지 않는다. 기존 검증이 성공한 빌드와 게임별 승인된 Universe/Place에만 기존 게시 단계가 자동 이어지게 한다. Open Cloud 키는 GitHub Actions Secret \`ROBLOX_OPEN_CLOUD_API_KEY\` 등 기존 코드가 참조하는 키를 사용하고, 키 원문은 GitHub나 문서에 절대 기록하지 않는다. 예제의 \`ROBLOX_OPEN_CLOUD_KEY\` 등은 실제 저장소 계약과 확인 후 맞춘다.
2. **코드 작성·자가 수정 루프:** 신규 Luau 모듈은 \`--!strict\`와 명시적 Player/Boolean/반환 타입을 기본으로 한다. 클라이언트 입력은 서버에서 자료형·거리·소유권·속도를 검증한다. 추가 코드가 다른 모듈에 순환 의존하지 않는지 검사한다. CI의 \`qa/simple-rpg-ai-authoring.test.mjs\`는 정적·연결·기존 책임 경계 회귀 검사이며 실제 Luau 타입 검사/엔진 실기기 테스트와 동일하지 않다. 기존 레거시 스크립트 전체에 \`--!strict\`를 무작정 붙이지 않는다.
3. **모바일 단축 명령:** "버그 수정 1번 시나리오" = AI 동료 소환→따라오기→전투/채집→해산 시나리오 확인 및 책임 소스 수정. "동료 AI 고쳐" = \`server/CompanionAI.luau\`, \`server/Game.server.luau\`, \`client/Game.client.luau\` 확인. "패링 수정" = 기존 \`civGuard\`/적 공격 판정·클라이언트 연출 확인. "자동 배포 상태" = 소스 리비전·F0~F9 파이프라인·승인된 Place 게시 기록을 읽어 실제 상태 보고. 메시지 길이와 무관하게 파일을 추측 생성하지 말고 책임 경로부터 확인한다.

### 오너 최신 자동승인 및 배포 지시
- 오너는 **전체 게임 자동 승인 및 플로우에 따른 자동 배포**를 원한다. 별도의 인간 클릭 승인·같은 검증을 배포 단계에서 다시 반복하지 않는다.
- **기존 플로우의 앞 단계 통과 증거를 재사용**하여 정본 게시 단계까지 연속으로 진행한다. 게임별 대상 매핑/인증 정보가 없거나, 앞 단계 PASS 및 실제 게시 증거가 없다면 자동 배포 **완료라고 허위 보고하지 않는다**. 중앙 실행 정책·보안 게이트를 무시하는 강제 게시 경로는 이 게임 문서에서 새로 만들지 않는다.
- 직접 개발 완료와 실제 Roblox 라이브 게시 완료는 별개 상태로 기록한다. 모든 게임 자동화 범위는 플랫폼 전역 권한/파이프라인으로 구현해야 하며, 대충알피지 문서만으로 다른 게임의 자동 게시가 활성화된 것으로 간주하지 않는다.

## 11. 1~3시대 자원→몹→아이템→유레카→종족 건축 인과관계 (2026-10-15 오너 요구)

### 비주얼·조작 기준
- R15 블록키+무광 손그림 텍스처, Future Lighting, 회청색 Atmosphere 안개, 고대 유적과 로우폴리 숲.

### 시대별 원본 인과관계
**석기:** Wood ×10 + Stone ×10 → 돌창(StoneSpear) → 야생 멧돼지(WildBoar) → 가죽(Hide) → '야생 몹 1마리 사냥' 유레카 / 관련 연구 비용 50% 할인 → 석제 성벽 + 고조선 단군 제단(테크 비용 추가 15% 할인).

**청동기:** CopperOre ×15 + TinOre ×15 → 용광로 청동 주괴(BronzeIngot ×5) → 청동검(BronzeSword) → 청동 골렘(BronzeGolem) → 코어 크리스탈(CoreCrystal) → '청동 주괴 5개 제련' 유레카 / 관련 연구 비용 50% 할인 → 이집트 피라미드(건축 액션 대기시간 20% 감소).

**철기:** IronOre ×20 + Coal ×20 → 고로 철 주괴(IronIngot ×5) → 철제 대검(IronGreatsword) → 암흑 철기 기사(IronKnight) → 다크 아이언(DarkIron) → '기사 몹 격파' 유레카 / 관련 연구 비용 50% 할인 → 로마 콜로세움(방어력 +15%)·바이킹 드라카르 조선소.

### 내가 직접 수정하는 실제 책임 경로

- client/Game.client.luau: 모바일 제작·장비·건축 화면, V/B 단축키 및 실제 서버 이벤트 연결.

### 기존 72개 연구와 시대 번호의 차이

### 보존/보안
- 기존 액션 ID `CivResearch`도 **동일** `civResearch`를 사용한다. 클라이언트가 전송한 임의 재고·연구 성공·피해량은 받아들이지 않는다.

- `SyncInventoryEvent`는 **클라이언트 → 서버 입력을 제공하지 않는** 단방향 복제이며 해당 플레이어에게만 전송한다. 서버의 숫자 어트리뷰트가 정본이다.
- DataStore `simple-rpg-development-v1`, 저장 레코드의 `player:<UserId>` 형식, 숫자 키/기존 보상·전투 수치는 보존한다. 저장은 기존 `UpdateAsync`/주기 저장/퇴장 저장에 맡기며 연구 때마다 별도 저장소에 중복 저장하지 않는다.
- 기존 대형 서버/클라이언트는 레거시 타입 불명 부분이 있으므로 파일 전체에 `--!strict`를 일괄 적용하지 않았다. 모든 신규 원격 판정은 기존 서버 검증 로직에 연결한다.

## 14. 모바일 자동 전투·스마트 패링·적 모션 예고 설계 (2026-10-15)

### 구현 순서 및 단일 책임
1. `server/Game.server.luau`: 서버가 `Remotes/AutoCombatEvent`를 생성한다. 모바일 자동 공격 입력의 액션/모델/쿨다운/거리/대상 소유권을 검증한 뒤, 기존 `civAttack` 공격 판정만 사용한다. 별도 `TakeDamage(15)`는 금지한다.
2. `client/Game.client.luau`: 모바일에서만 초기 ON 상태의 자동 전투 토글·주기 0.4초 탐색·15스터드 범위의 **문명 적만** 골라 서버로 요청한다. 다시 생성된 캐릭터를 따라가며, 다른 플레이어/동료/무해한 몹을 타격 대상으로 삼지 않는다. 키보드 C/E/F·회피 Shift 및 기존 터치 버튼을 보존한다.
3. 실제 공격 예고 타이밍 `enemy.TelegraphAt`에 대응한 `IsPreparingAttack` 속성/클라이언트 경고를 기존 적 전투 FSM에서 갱신한다. 랜덤 `math.random()` 공격 예고값은 사용하지 않는다. 스마트 자동 패링은 자동 전투가 켜지고 서버가 본인에게 향한 예고 공격임을 검증한 상황에서 기존 `civGuard`의 쿨다운/0.25초 기본 패링 판정을 그대로 따른다.
4. 모바일 스와이프/터치 동작은 화면 HUD와 월드 제스처가 충돌하지 않게 제한한다. 이동은 Roblox 기본 모바일 조이스틱을 활용한다.
5. QA: 원격 이벤트 생성 주체(서버), 정상/잘못된 적 모델 거부, 공격속도 제한, 패링 타이밍, 초기 ON 및 OFF, 0.4초 요청 제한, 화면 버튼 충돌, 재접속·서버 저장 유지. 실물 모바일 및 Roblox 엔진 검증은 별도 필요.

### 오너가 제공한 마스터 스크립트 원문 1
지정 예시 경로: `StarterPlayer/StarterPlayerScripts/UIAutoLayoutFix.client.luau`. 요구: `UIListLayout` 동적 생성, `LayoutOrder` 정렬, 8픽셀 간격.

```luau
--!strict
local Players = game:GetService("Players")
local LocalPlayer = Players.LocalPlayer
local PlayerGui = LocalPlayer:WaitForChild("PlayerGui")

local function FixUIOverlaps()
	local mainGui = PlayerGui:FindFirstChild("TechTreeGui") or PlayerGui:FindFirstChildOfClass("ScreenGui")
	if not mainGui then return end

	for _, child in mainGui:GetDescendants() do
		if child:IsA("Frame") and not child:FindFirstChildOfClass("UIListLayout") then
			-- 겹침 방지를 위한 자동 리스트 레이아웃 주입
			local listLayout = Instance.new("UIListLayout")
			listLayout.SortOrder = Enum.SortOrder.LayoutOrder
			listLayout.Padding = UDim.new(0, 8)
			listLayout.Parent = child
		end
	end

	print("[UI Fixer] 모바일 UI 레이아웃 자동 정렬 및 겹침 방지 적용 완료")
end

task.spawn(FixUIOverlaps)
```

### 오너가 제공한 마스터 스크립트 원문 2
지정 예시 경로: `StarterGui/MobileHUDManager.client.luau`. 요구: 텍스트·버튼 ZIndex 5, 프레임 ZIndex 2 및 모바일 HUD 가림 방지.

```luau
--!strict
local Players = game:GetService("Players")
local LocalPlayer = Players.LocalPlayer
local PlayerGui = LocalPlayer:WaitForChild("PlayerGui")

local function OptimizeZIndex()
	for _, gui in PlayerGui:GetChildren() do
		if gui:IsA("ScreenGui") then
			gui.IgnoreGuiInset = true
			for _, descendant in gui:GetDescendants() do
				if descendant:IsA("TextLabel") or descendant:IsA("TextButton") then
					descendant.ZIndex = 5 -- 텍스트가 항상 최상위에 오도록 설정
				elseif descendant:IsA("Frame") then
					descendant.ZIndex = 2
				end
			end
		end
	end
	print("[UI Fixer] ZIndex 계층 구조 재정렬 완료")
end

task.spawn(OptimizeZIndex)
```

### 실제 게임 구현 시 단일 책임·안전 조건
1. 사용자 코드 **원문은 요구 자료로 보존**한다. 현행 Rojo 프로젝트는 `client/`를 `StarterPlayerScripts/GameClient`에 연결하므로, 두 스크립트를 무조건 추가해서 기존 UI 제어와 경쟁시키지 않고 **대충알피지의 기존 HUD/테크트리 생성 코드**에서 목적을 구현한다.
2. `UIListLayout`은 목록형 컨테이너에만 필요하며, 모든 Frame에 무차별 주입하면 체력바·장비 슬롯·팝업·스크롤·퀵슬롯의 절대 좌표가 깨질 수 있다. `UIGridLayout` 등 기존 레이아웃이 있는 컨테이너를 덮지 않는다. 대상 메뉴에 `LayoutOrder`와 `Padding = UDim.new(0, 8)` 원칙을 적용한다.
3. 텍스트·버튼 5, 프레임 2의 상대적 계층 목표를 유지한다. 다만 모든 자손의 ZIndex를 강제하면 모달/툴팁/닫기 버튼/다른 ScreenGui가 가려질 수 있으므로 실제 개별 패널 단위 계층을 정리하고 `ZIndexBehavior`를 고려한다.
4. `IgnoreGuiInset = true` 전역 강제는 상단 노치/시스템 영역과 충돌할 수 있다. `GuiService:GetGuiInset()`·안전 영역·가변 화면 비율에 따라 상단 상태바와 좌측 버튼의 위치·간격을 보정한다.
5. UI가 늦게 생성되거나 다시 열릴 때도 레이아웃이 중복 생성되지 않게 한다. 동적으로 생성되는 연구창, 가방, 모바일 전투 토글, 제작·무역 버튼을 포함하고 PC/모바일 조작을 유지한다.
6. **지시 및 문서 기록과 실행 코드 반영은 별개**다. 이 문서 커밋만으로 모바일 버그 수정/새 Roblox 버전 게시가 완료됐다고 주장하지 않는다.

## 24. 멀티버스 포털 광장 그래픽 구현 (2026-10-15)

- **문명별 대표 아치:** 기존 24개 포털 패드의 위치와 접촉 이동 코드는 그대로 두며, 그중 **로마 1·이집트 2·바이킹 12·고조선 15** 포털 뒤에 비충돌 석주 2개·관석·반투명 차원광을 추가한다. 각 문명은 붉은 돌·앰버·딥 블루·이끼색으로 구별한다. 나머지 20개 포털도 계속 이동할 수 있다.
- **충돌 안전:** 추가 장식은 기존 `civPart(..., false)`로 `CanCollide=false`로 생성하고 `CanTouch=false`, `CanQuery=false`를 명시한다. 플레이어·채집·전투·서버 레이 검사·포털 `Touched` 판정을 막는 실체가 되지 않는다.

## 25. 오너 검증 기준 변경 — Open Cloud API 필수 (2026-10-16)

- **Roblox Studio 직접 실행은 필수 게이트가 아니다.** Studio 미실행만으로 대충알피지의 개발·게시를 차단하거나 실패로 판정하지 않는다.
- **Roblox Open Cloud API는 필수다.** 기존 오너 전용 `.github/workflows/owner-simple-rpg-direct-publish.yml`을 그대로 사용하며 승인된 `simple-rpg` 전용 Universe/Place에 게시한다. 새 게시 파이프라인·다른 게임 대상·권한 우회는 만들지 않는다.
- 인증은 기존 GitHub Actions Secret `ROBLOX_OPEN_CLOUD_API_KEY`를 사용하며 키 원문을 소스·로그·문서에 남기지 않는다. 권한 누락·API 오류·응답 불일치·게시 버전 확인 실패는 배포 검증 실패로 기록한다.
- 필수 증거는 **정확한 main 소스 SHA, API 게시 요청/응답 성공, 해당 전용 Place의 실제 게시 버전 확인**이다. 로컬 정적 QA와 Rojo 패키지 검증은 별도 유지하되 Studio 실행 증거를 필수로 요구하지 않는다.
- Open Cloud API 게시 성공은 몬스터 AI·전투·화면·모바일·DataStore 재접속 실플레이 검증을 대체하지 않는다. 미확인 항목은 `미검증`으로 유지한다.

## 26. 오너 에셋 병합 원칙 — CC0 우선·일부 수정 허용 (2026-10-17)

- **기본 우선순위:** 저장소의 기존 CC0 원본 검색 및 라이선스 확인 → 적합한 기존 에셋 그대로 적용 → 게임 표현에 필요한 최소한의 부분 수정 → 기존 에셋으로 충족할 수 없는 요소만 신규 제작. **신규 제작 일괄 금지가 아니다.**
- **수정 허용:** 기존 모델·이미지·효과음의 색상, 크기/비율, 재질, 텍스처, 폴리곤/리깅/애니메이션 호환성, 성능 최적화, 게임에 맞는 구성 및 일부 형상 변경. 원본 전체를 불필요하게 새로 만들지 않는다.
- **원본 보존:** `assets/external/simple-rpg/`, `assets/roblox/actors/sources/` 등 저장소에 이미 확보한 원본은 훼손하지 않는다. 수정판은 원본과 구분하고 출처·CC0 근거·변환 및 수정 이력·대상 용도·해시/에셋 ID를 추적한다. CC0 여부가 미확인된 파일은 임의로 CC0이라고 간주하지 않는다.
- **실제 게임 연결:** 기존 `roblox-games/simple-rpg/`와 `.github/workflows/owner-simple-rpg-direct-publish.yml` 및 이미 있는 에셋 등록 책임을 사용한다. 업로드된 Roblox ID, Universe 사용 권한, 실제 `CreatureModels`/기존 UI/월드 프리팹 바인딩, 동일 Place 게시 증거를 구분해 확인한다. 별도 배포 파이프라인·무관한 게임 모델·가짜 대체 에셋 추가 금지.
- **안전과 호환:** 몬스터 종별 외형을 맞춰 적용하며 휴머노이드 모델을 야생동물인 것처럼 무차별 대체하지 않는다. 기존 적 AI·히트박스·충돌·R15·모바일 프레임, `simple-rpg-development-v1` 저장 키, 전투/연구/경제 밸런스, 비공개 Place 정체성은 보존한다.
- **수용 기준:** 원본 확보 ≠ 변환 완료 ≠ Roblox 업로드 ≠ 게임 적용 ≠ 게임 게시. 각 단계는 실제 검증 증거가 있을 때만 완료로 표시한다. 기존 검증을 재사용하고 변경 책임에 필요한 검사만 수행한다.
- **현재 상태:** 저장소에 보관한 CC0 아카이브와 GLB 원본은 재사용 후보이며, 원본 파일 존재만으로 게임의 3D 모델 자동 적용 또는 최신 Roblox 게시가 완료됐다고 주장하지 않는다. 이 절의 병합은 에셋 작업 지침 갱신이지 Roblox 플레이스에 새 에셋을 삽입한 증거가 아니다.

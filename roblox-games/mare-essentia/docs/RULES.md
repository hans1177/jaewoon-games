## 에셋
- 승인된 CC0 에셋만 쓴다(`assets-registered.json` / `AssetIds.luau`). AI 생성·실존 인물 이미지 금지(단, 아래 '오너 제작 원화'는 예외). **2026-11-17 오너 지시로 기존 자산이 부족한 3D 원본에 한해 검증된 외부 다운로드를 허용**한다. 출처 불분명·NC·유료·인공지능 생성 모델은 사용하지 않는다.
- 소스가 쓰는 모든 에셋은 `tools/devloop/asset_check.py` 가 검사한다. `tests/run.sh` 에 포함돼 있어 오타·미등록은 배포 전에 걸린다.

### 외부 3D 부족 자산 보완 규칙 (오너 승인 2026-11-17)
- 우선 기존 에셋에서 정확히 일치하는 실물 모델을 확인한다. 없으면 **무료 CC0 완성형 원본**을 제작자 공식 페이지에서 받는다. 색상만 바꾼 대용 건물/파트·절차형 대체물/허위 실물 등록은 금지한다.
- 다운로드 전에 국가·시대·건물 실제 용도(조선 관아 ≠ 한양 왕궁, 일본 성 ≠ 사원, 군영 ≠ 궁정 본관)를 대조한다. 모델의 저작권자·원본 URL·무료 CC0 라이선스·생성 방식·Roblox 업로드 가능 여부를 확인한다. 인공지능 제작 여부가 미확인이면 후보 보류.
- 원본을 `assets/inbox/<종류>/`에 두고 같은 이름의 `.license.json`에 원저자/원본 URL/CC0를 기록한다. SHA-256·금지 해시·중복을 점검한 후 기존 `tools/devloop/register_asset.py` → `owner-mare-essentia-assets.yml` → `AssetIds.luau` 경로만 사용한다.
- Roblox Universe 권한·실제 메시·재질·모바일 화면 검증 전에는 `productionVerified`로 판단하거나 왕궁 외형을 교체하지 않는다. 로컬 다운로드 오류·원본 검증 실패는 **미적용**으로 표기한다. 에셋 업로드 실패가 자동 배포 우회 근거가 되지 않는다.

## 통합 3D 재질 제작 표준 (복식·건축·선박·소품)

> 적용 범위: 주민·동료·전투 NPC, 가축, 복식·장신구·무기, 주거·시장·농장·종교·공방·행정·항구 건축물, 지형·도로, 선박·실내 소품. **새 자산과 기존 자산의 재질 개선 작업에 적용**한다. 이 문서는 제작 기준이며, 작성만으로 실제 텍스처 다운로드·업로드·배포·모바일 검증이 끝난 것은 아니다.

### 1. 아트·원본 보호 원칙

- 전역 화풍은 **반실사**. 실제 소재의 무광·반사·요철·결은 살리되 형태, 색상 가독성, 시대·문화권 실루엣이 우선이다. 재질이 모델을 대신해서는 안 된다.
- **원본 메시·UV·텍스처·PBR·자산 ID·스케일·관절·충돌·저장·경제·전투·발전도 불변**이 기본이다. 정상적인 원본 ColorMap/NormalMap/RoughnessMap/MetalnessMap/TextureID를 임의 덮어쓰거나 제거하지 않는다.
- **모델과 텍스처는 별개**다. 텍스처만 다운로드해도 UV가 없는 GLB에 자동 적용되지 않는다. 실제 모델의 UV와 텍스처 반복/절단·방향·경계, 수입 후 Roblox 표시를 먼저 확인한다. UV가 없으면 승인된 원본의 UV 수정·재수입 경로를 거치며 기존 모델에 임의로 색칠해 완료 처리하지 않는다.
- **작은 돌기**는 가죽 엠보싱·회벽 입자·석재 표면·단조철 망치자국 등의 미세 요철을 뜻한다. 레고 블록처럼 눈에 띄는 큰 돌기·불필요한 실제 폴리곤 추가 금지. 반복 돌기와 바느질·로프 꼬임은 적절한 UV가 있는 경우 노멀맵 중심으로 처리한다.
- 문화권/시대/실제 용도에 맞는 승인 실물 모델만 사용한다. 왕궁·관아·사원 등의 외형을 재질·색상만 바꿔 다른 국가의 건물로 대체하지 않는다.
- 새 외부 재질은 **무료 CC0·제작자 공식 원본 URL·작가·라이선스·파일 해시·Roblox 사용권**이 확인된 것만 사용한다. 유료·NC·출처 불명·권리 미확인 텍스처 금지. 기존 `assets/inbox/` → `.license.json` → `register_asset.py` → 기존 등록/게시 흐름을 따른다. 이미지 승인 규칙도 해당되는 경우 적용한다. 새 재질 은행이나 중복 업로드/별도 파이프라인을 만들지 않는다.

- **원본 색상 유지:** 전체 색상을 갈색으로 덮거나 모델 모든 부품을 동일 재질로 통일하지 않는다. 원본 PBR이 없거나 수입으로 소실된 부품만 근거 있는 복원을 시도하고 실물 화면으로 확인한다.

### 3. 지역·발전도별 건축 재질 배정

- **지역 정본:** `PortCultures.luau`의 `STYLE/PROFILE/OUTFIT/REGION`과 `Ports.country`·연도·기후·건물 실제 용도를 먼저 확인한다. `PortScene.luau`, `PortBuildings.luau`는 기존 책임 분기를 재사용한다. 새 문화권 이름이나 가짜 지역용 실물 모델을 임의로 추가하지 않는다.
- **지중해·이베리아:** 석회 회벽·밝은 석재·테라코타 지붕, 부두는 목재/석재.
- **영국·한자·네덜란드:** 지역별 벽돌·석재·목재 골조, 도시와 공공건물은 용도에 맞는 기와/슬레이트.
- **북유럽:** 목조·판재·석재 기반, 널·슬레이트 지붕. 농촌은 승인된 실제 초가/목조 원본이 있는 경우만.
- **그 외 문화권:** 해당 국가의 전통 재료·기후·용도를 개별 확인한다. 유럽식 재질이나 건물 모델 일괄 강제 금지.
- **발전도 1~5:** 초기 건물은 소박한 재료와 낮은 가공도, 발전 단계가 오르면 실제 해금된 건물의 가공 석재·정돈된 목재·장식 금속 품질이 보이게 한다. **발전도·건물 크기·위치·생산량·교역·저장 키는 재질 변경 명목으로 바꾸지 않는다.** 기존 완공물의 재방문 공사를 반복하지 않는다.

### 4. 파일·지도·로블록스 적용 기준

- **파일명:** 재질/소재 식별자는 `mat_<분류>_<종류>_<변형>`; 텍스처는 같은 기본명에 `_bc`(기본색), `_n`(노멀), `_r`(거칠기), `_m`(금속성)를 붙인다. 예: `mat_fabric_wool_navy_bc`, `mat_leather_pebbled_brown_n`, `mat_wall_plaster_light_r`. 기존 에셋 ID·이름은 호환성 때문에 임의 개명하지 않는다.
- **맵 순서:** 기본색 → 노멀 → 거칠기 → 금속성. 모든 맵이 필수는 아니며 UV·맵 좌표·수입 권한·성능이 확인된 맵만 연결한다. AO는 필요할 때만 원본 베이킹/지원 형식에서 사용한다.
- **로블록스:** UV가 올바른 `MeshPart`의 승인된 외형 맵은 `SurfaceAppearance` 우선. 재사용하는 바닥/벽면은 지원되는 기본 재질·`MaterialVariant`를 기존 시스템에서 재사용. 서로 다른 재질 인터페이스를 강제로 뒤섞거나 원본 색상/표면을 무단 덮지 않는다.
- **모바일 권장:** 일반 반복 표면의 시작점 512px, 주요 인물/대표 건축물 최대 1024px를 우선 검토. 2048px는 실측 성능·메모리·화면 품질 근거가 있을 때만 예외 승인한다. 수치는 품질 상한 확정치가 아니라 **검수 시작점**이며 UV·반복도·Atlas/공유 텍스처가 실제 화질을 결정한다.
- **거리별 품질:** 기존 NPC 복식 거리/FPS 단계와 건축·선박의 기존 로딩/LOD 구조를 유지한다. 멀리서 마이크로 노멀·고주파 무늬가 번쩍이지 않게 조절하되 원본 메시·재질의 의미를 바꾸지 않는다.
- **실물 없는 항목:** 텍스처만 임의로 붙이거나 기본 `Part`·자동 생성 원형 메시·유사 건물로 대체하지 않는다. 승인 가능한 실제 원본이 없으면 부족 자산으로 기록하고 적용 보류한다.

### 5. 적용 및 품질 판정

1. **사전 확인:** 최신 중앙정책 4개 → `AGENTS.md`·이 `RULES.md` → 실제 `AssetIds.luau`·`assets-registered.json`·기존 GLB/UV/PBR/라이선스/등록 상태 확인.
2. **자산 준비:** 기존 승인 자산 재사용 우선. 부족할 때만 허용된 CC0 원본을 받아 공식 출처·저작권·SHA·UV·동일 항목 중복·기기 메모리를 검증. `assets/inbox/`와 기존 등록 경로만 이용한다.
3. **책임 함수 적용:** 인물은 기존 `Pose.luau`·`AssetLoader.server.luau`, 건물은 기존 `PortCultures.luau`·`PortScene.luau`·`PortBuildings.luau` 등 실제 소유 흐름에 직접 적용. 임시 래퍼·우회용 재질 덮개·새 파이프라인 금지.
4. **기존 검사:** `tests/run.sh`·기존 에셋 등록 검사·문화권/교역/저장/전투 회귀 검사 실행. **정적 코드 검사만으로 재질 품질 통과 선언 금지.**
5. **실물 검사:** Roblox 수입 자산의 흰색/누락 텍스처·법선 방향·금속/직물 반사·UV 이어짐·머리/가축/장화/지붕/도로의 근·중·원거리 가독성 확인. `MareOutfitMaterialAuditState` 등 기존 Studio 감사 속성은 수집 결과일 뿐 기기 화면 검증을 대신하지 않는다.
6. **기기·배포:** 모바일 저사양/고사양, PC, 낮/밤, 비·안개 등 해당 조건에서 프레임/메모리/깜빡임/반복 무늬를 확인. 기존 오너 승인 `main` → 비공개 Roblox 게시 → 동일 리비전·Place 검증 경로만 사용. 작업 전후 화면을 비교하고 실패 시 책임 소스/원본을 수정해 재검증한다.
7. **완료 판정:** 소스 반영, 승인 원본·라이선스, 등록·권한, canonical QA, 실제 Roblox 게시, 모바일/PC 시각 검증이 **각각 확인된 범위에서만** 완료라고 기록. 하나라도 확인하지 못하면 **미검증/보류**, 실패하면 **실패**로 표기한다.

# 대륙·국가별 건물 (BUILDINGS_CATALOG.md 의 지역 편)

각 줄: **식·의·주(생산)** / **교역·산업** / **공공·종교** / **연결 학문**. 시대는 게임 배경(1500~1800년대) 기준.
역사적으로 알려진 특산·제도만 쓰며, 세부 수치는 구현 전 출처 확인. 외형은 승인된 에셋만 사용.

## 6. 가상 7번째 대륙(아스테리아, 사용자 설정 전까지 비움)
고유 양식과 건물은 사용자 설정 후 추가. 지금은 `lost_astheria_*` 카드와 해도만 연결.

## 연결 규칙
- 각 국가 줄은 `Buildings.luau`에서 `region`(대륙)·`nation`(국가)·`category`(식/의/주/산업/공공/종교)·`disc`(학문)·`minLevel` 필드로 데이터화한다.
- 항구는 `PortCultures.REGION` 의 양식 → 국가 → 건물 목록으로 이어 붙인다 (새 문화권은 표 한 줄 추가).
- 같은 건물이라도 국가마다 이름·외형 스킨이 다르다 (예: 목욕탕 = 함맘 / 센토 / 로마식 테르마이).

## 바이브 왕궁·생산·궁정 주민 제작 지시문 (2026-11-17)

> 대상: Mare Essentia의 기존 `PortScene.luau`, `PortBuildings.luau`, `PortCultures.luau`, `Ports.luau`, `ProductionChains.luau`와 기존 `View.luau`의 읽기 전용 화면 데이터. 이 절은 바이브가 따라야 할 게임별 상세 **설계 지시문**이며 자체적으로 완료/출시 권한이 아니다. 중앙정책·`AGENTS.md`가 항상 우선한다.

### 1. 왕궁 외관: 바이브 구현 프롬프트

**목표:** 궁전 본체가 커다란 단색 상자와 공통 지붕으로 보이지 않게 한다. 각 항구의 건물은 실제 국가·통치형태·시대에 맞는 **입면, 지붕 실루엣, 문, 회랑, 탑, 중정, 재료, 장식, 조경, 경비 시설**을 구분한다. 멀리서는 윤곽, 중거리에서는 건축 부속, 가까이에서는 문·창호·장식과 생활이 보이도록 한다. 동일한 왕궁 바탕에 색만 바꾸는 작업은 개선 판정 금지.

**정체성 결정 순서:** `Ports.Ports[portId].country` → 해당 항구의 왕궁/총독부/관아 보유 여부와 `palaceName` → `info.year`(시대·지배권 변화) → `PortCultures.REGION`(재료·의상) → `info.level`/`info.sim.stage`(규모·증축). `currentKey` 하나만으로 왕궁 국가를 판단하지 말 것. 왕궁이 없는 도시에는 새로운 왕궁을 임의 건설하지 말고 기존 관청·총독부만 표현한다.

| 아메리카·동남아·태평양 | 실제 식민 행정관저 또는 현지 궁정·관아의 고상 목조/열대 회랑·넓은 처마; 항구의 국가·시대별로 분리 | 식민지 총독부를 토착 왕궁이라 부르거나 열대 전체 한 모델 금지 |

**제작 우선순위:** 기존 승인된 고품질 지역 건물 모델 → 실제 고증과 라이선스·해시·유니버스 사용권이 검증된 무료 3D 모델. 지역 고유 **완성형 모델/부재가 없으면 해당 자산을 누락 목록에 남기고 작업을 보류**한다. 기본 `Part`/구체/원통·건축용 임의 도형·의미 없는 대체 자산·소스 없는 AI 모형 금지. 기존 왕궁 실루엣은 검증된 대체가 나오기 전까지 훼손하지 않는다.

**배치:** 기존 왕궁 필지·왕궁 건립 판정·알현 버튼·카메라·주거/도로 충돌 영역 그대로 유지. 같은 필지에서 정문 → 전정 → 본관 → 측랑 → 정원 → 근위대 숙소/마구간 → 서고/행정관 순서로 기능이 읽혀야 한다. 시대·발전도 상승 시 같은 양식의 확장 요소만 추가한다. 멀리 있는 디테일은 생략하고 카메라 근처 승인 자산만 표시한다.

### 2. 특산품 생산 시각화: 바이브 구현 프롬프트

- 입력 기준: `Ports.produces`, `ProductionChains.ClassOf`/`Recipes`/`craftable`, 기존 `info.sim.buildings`/`info.sim.industries`. **새 경제 루프·품목 ID·저장 키·레시피·생산량을 만들지 않는다.**
- 화면의 4단계 동선: **원료 입고**(원산지 품목 자산) → **실제 작업 장비**(제련·직조·압착·제당·제재 등 일치하는 설비) → **기존 레시피의 완제품**(정확한 자산이 있을 때만) → **수레·시장·부두**. 공정이 승인된 자산과 실제 게임의 생산/산업 상태로 증명될 때만 해당 단계 표시.
- 예: 면화는 직조 공방·직물 적재, 철은 제련/대장간·공구 적재, 사탕수수/설탕은 제당·운송, 생선은 어시장·건조/염장, 목재는 제재·선박 부재. 원산지 브랜드는 `ProductionChains.BrandsByPort`를 우선 사용.
- NPC는 기존 `Pose` 직업 모션·상품 소품 및 보행자 경로만 재사용해 농장→공방→시장→부두를 오간다. 연출은 **표시용**이고 서버 교역/시세/재고 판정에 관여하지 않는다.
- 모바일은 가까운 작업장 한두 곳을 우선 보여 주고, 화면 밖 소품·작업 모션 생성을 제한한다. 실제 바뀐 생산/건설 상태에서만 재구성하며 전체 월드를 매 프레임 재생성하지 않는다.

### 3. 왕궁 직업과 인원: 바이브 구현 프롬프트

- 기존 `RoyalCourtPopulation`, `info.sim.residents`, `info.sim.prosperity`, `palaceTier`를 사용한다. 기존 시각용 왕궁 종사자를 별도 경제 직업표나 거주자 수로 더하지 않는다. 실제 인구·고용 수치 변경을 원하면 기존 저장·경제 마이그레이션과 검증이 먼저 필요하다.
- 역할: **근위병·성문 경비·순찰병·궁정 시종·왕실 서기·문서 전달원·정원사·마구간 관리인·주방 일꾼·궁정 학자·행정 관리**. 직업별 `Job`·`Workplace`·`Activity` 속성으로 표시, 기존 `villager`·`walkers`·`Pose.work` 흐름 안에서 구분한다.
- 최소 구성: 궁문에는 경비, 본관에는 시종, 행정실에는 서기. 상위 왕궁 단계에서 정원사·마구간 관리인·학자·전령 등 **기존 시설이 실제 표시될 때만** 직업이 열린다. 부속 시설이 없으면 그 직업 주민은 생성하지 않는다.
- 생활: 아침 경비 교대·청소·마구간 업무, 낮 알현·서류·전령·정원, 저녁 연회 준비·야간 순찰. 경비를 전부 주점으로 보내거나 야간 궁문을 무인으로 두지 않는다. 기존 지역 의복·모자 및 `Lighting.ClockTime` 기반 일과 사용.
- 주민 수는 기존 항구 인구와 왕궁 단계에 비례시키고 낮은 인구·불황은 적게 표시. 모바일에는 가까이 보이는 인원만 활성화하고, 존재하지 않는 실제 시민을 경제 지표에 추가하지 않는다.

### 4. 검증·완료 기준

- 대표 항구 최소 1곳씩 조선/중국/일본/인도/오스만/유럽/아프리카/열대 지역의 **실제 화면**을 앞·측면에서 비교. 동일 색상/부재 교체만으로 지역 고유 왕궁이라고 판정하지 않는다.
- `PortScene`의 왕궁·시장·생산·부두 동선 간 충돌과 건물 내부 진입, 시설 버튼, 기존 주민 직업 모션을 점검한다.
- 1~5단계, 인구·불황 변동, 새벽/낮/저녁, 모바일 메모리·프레임과 자산 사용권을 확인한다.
- 기존 교역·탐험·저장·경제 값 회귀 검증과 기존 게임 배포/런타임 증거를 별도로 확인한다. **프롬프트 갱신이나 코드 정적검사만으로 실제 왕궁 3D·플레이·게시 완료 선언 금지.**

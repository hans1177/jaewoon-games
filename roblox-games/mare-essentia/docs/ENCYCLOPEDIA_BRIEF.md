## 2. 해설 데이터 형식 (글 작업 — ChatGPT)

```lua
Articles.<card_id> = {
	topic = "<위키 영문 표제>",            -- 기존 칸 유지
	latin = "<학명 또는 원어 표기>",        -- 동식물 학명, 유물·유적은 원어
	summary = "<개요 2~3문장, 120~200자>",
	looks = "<생김새·구조 3~5문장, 크기·색·재질 숫자 포함>",
	details = "<쓰임·특징 3~5문장>",        -- 기존 칸(길게 다시 씀)
	context = "<그 시대 항해자·상인에게 어떤 의미였나 2~4문장>", -- 기존 칸
	history = "<역사 3~6문장, 연도 포함>",  -- 기존 칸
	facts = { { "분류", "..." }, { "지역", "..." }, { "시대", "..." }, { "크기", "..." }, { "쓰임", "..." } }, -- 요약 상자 4~6줄
	trivia = "<알고 나면 재미있는 한 가지, 1~2문장>",
	sources = { "<참고한 공개 자료 이름>" },  -- 위키백과 문서명 등. 링크 X
}
```

- **분량**: 한 장당 본문 합계 600~1,000자(한국어). 짧은 설명(`description`)은 그대로 두고 카드 앞면용으로 쓴다.
- **사실만**: 연도·숫자는 공개 자료로 확인된 것만. 모르면 쓰지 않는다. 전설·추정은 "~라고 전한다"로 구분(`meta.evidence`).
- **쉬운 말**: 중학생이 읽을 수 있게. 전문 용어는 처음 나올 때 괄호로 풀이.
- **분야별 꼭 넣을 것**
  - 동물(Zoology): 학명 · 몸길이/몸무게 · 사는 곳 · 먹이 · 그 시대 사람과의 관계(식량·가죽·두려움)
  - 식물(Botany): 학명 · 키/잎·꽃 모양 · 자라는 기후 · 쓰임(약·향신료·염료) · 교역 경로
  - 광물(Mineral): 화학식 · 색/굳기(모스) · 산지 · 제련·쓰임
  - 유적(Site): 위치 · 지은 시기와 사람들 · 크기 · 남은 모습 · 발견·재발견 이야기
  - 유물(Relic): 재질 · 크기 · 만든 곳·때 · 쓰임 · 지금 있는 곳(박물관)
  - 지리·날씨·항해: 원리 그림으로 설명할 수 있게 단계별로
  - 교역품(Goods): 원산지 → 거쳐 간 항구 → 팔린 곳, 그 시대 값의 감(비싼/흔한)
- **납품 방법**: 분야별 50장씩 묶어 위 형식 Lua 그대로. 파일 `docs/encyclopedia/<분야>_<번호>.luau` 로 저장소에 올리면 Claude가 `Articles`에 합친다.

- 일반 메뉴·카드 격자와 달리 왼쪽은 큰 원화, 오른쪽은 해설. 세로폰은 각각 한 페이지. 그림에 제목이나 버튼을 겹치지 않는다.

## 11. 분야별 기괴한 중세 고딕 문양 독립 원본 제작 프롬프트 (2026-11-28 오너 지시)

**이 절은 모든 후속 원화 제작자에게 필수다. 분야 문양 전용이며 기존 카드·지식 원화의 화풍이나 원본을 바꾸지 않는다.**

### 공통 프롬프트 (아래 분야별 프롬프트 중 정확히 한 줄만 결합)

> 14~15세기 중세 유럽 고딕 성당의 석조 조각, 채색 필사본과 희귀 고서에서 떼어낸 듯한 분야별 문장 하나. 고풍스럽고 기괴하며 신비로운 분위기. 중세의 수작업 세밀화와 금박 장식, 세밀한 잉크 선, 절제된 입체 명암, 풍화된 상아색 석재와 낡은 청동·흑철, 바랜 청금석·진홍색 안료. 분야에 맞춰 뾰족한 아치·삼엽 또는 사엽 문양·첨탑·가시덩굴·괴수 석상·고딕 트레이서리를 선택하여 차별화한다. 주제의 실루엣은 단순하고 강하게, 세부는 가까이서 볼수록 정교하게. 정사각형 1024×1024 이상 고해상도 풀컬러 원본, 가운데 독립 문장 하나, 전체 장식이 잘리지 않도록 사방 8~12% 여백, 실제 알파 투명 배경. 글자·숫자·리본 문구·로고·워터마크 없음. 과도한 금속 광택·네온·발광·현대적 플라스틱·카드형 상자·배경 풍경·검은색 배경·갈색 그라데이션·격자·전체 메뉴 목업 금지. 문양 바깥에 색 번짐이나 테두리 잔상이 없어야 한다. 작은 화면에서도 한눈에 분야를 알아볼 수 있게 묘사한다.

### 제작·검수·등록 순서

1. 생성 요청 한 번에 한 분야·한 원본만 제작한다. 참고 시트는 **화풍 및 분야별 구성 참고용**일 뿐, 전체 시트를 다시 그리거나 잘라서 고해상도 독립 원본으로 가장하지 않는다. 동일 가고일·동일 틀의 색상 변경을 여러 분야에 재사용하지 않는다.
2. 다음 분야로 이동하기 전에 기존 원본의 파일명·실제 이미지·규격·주제·알파·해시·검수 여부를 확인한다. 이미 적합한 원본은 재생성하지 않는다. 틀린 그림은 해당 분야만 재제작한다. 16종의 진행 상태를 실제 파일 기준으로 기록한다.
3. 독립 원본은 등록 감시 폴더 밖의 원본 보관 위치에 보존한다. 기존 원본과 승인 기록을 삭제하거나 임의로 덮어쓰지 않는다. 기존 원본과 신규 후보를 구분한다.
4. 검수된 16종만 4×4, 1024×1024 게임용 RGBA 시트로 합성한다. 칸당 256×256, 원본 비율 유지, 중앙 배치, 사방 최소 8% 여백, 이웃 칸 침범 없음. 원본을 변형해 세로로 늘이거나 자르지 않는다. 36~64픽셀에서 분야 구분을 확인한다.
5. 실제 알파값·풀컬러·해상도·중복 해시·칸 순서·가장자리 색 번짐과 권리를 검사한다. 검정색/갈색 불투명 배경은 투명 원본으로 인정하지 않는다. 원화의 실제 검수 전에는 승인이나 완료로 기록하지 않는다.
6. 최종 합성 시트만 기존 `/Vibe2Transfer/inbox/CardArt/ency_tab_sheet.png` 등록 경로에 넣는다. 기존 시트 교체는 원본 보존과 기존 등록 절차에 따른다. 새 등록 키·우회 등록기·유료 서비스 추가 금지. 실제 등록 번호와 게임의 분야 매핑·모바일 표시·배포를 확인한다.

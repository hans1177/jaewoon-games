# Roblox 게임 소스

`COMPANY_FLOW.md`의 Roblox 기본 플랫폼 정책을 실제 소스 구조로 구현하는 루트다. 정책 원본은 항상 `COMPANY_FLOW.md`이며 이 문서는 작업 규칙 미러다.

## 현재 Roblox 개발 세트

현재 메인 Roblox 개발은 서로 다른 핵심 루프와 기술 경험을 확보하는 6분류 대표 세트로 운영한다.

1. `ROLEPLAY_LIFE_AVATAR`
2. `SIMULATOR_TYCOON_INCREMENTAL`
3. `BATTLEGROUND_FIGHTING_SHOOTER`
4. `SURVIVAL_HORROR_ESCAPE`
5. `OBBY_PARTY_MINIGAME`
6. `STORY_RPG_ADVENTURE_RPG`

- `STORY_RPG_ADVENTURE_RPG`는 필수 분류다. 후보가 근거 기반으로 제외되면 같은 분류에서 재설계 또는 reseed한다.
- 6개 대표 게임은 모두 개발 대상이며 모두 출시 후보지만 6/6 출시는 강제하지 않는다.
- 6분류는 게임 수 상한이 아니다. 5개 부서 점수와 근거가 충분하면 강한 분류에 추가 게임을 확장할 수 있다.
- seed/design은 전체 세트에서 진행할 수 있고 실제 구현은 기본 2~3개 우선 병렬을 권장한다. 이는 WIP 가이드이며 포트폴리오 제한이 아니다.
- 분류가 달라도 핵심 루프가 실질적으로 중복되는 활성 후보는 만들지 않는다.
- 포트폴리오 전체에서 저장, 멀티플레이 서버/클라이언트 경계, PvP, NPC/퀘스트, 라운드/절차형 세션, 모바일 UI 경험을 가능한 한 분산 확보한다. 모든 게임에 모든 항목을 강제하지 않는다.

## 규칙

- 게임별 소스는 `roblox-games/<game-id>/` 아래에 둔다.
- 기존 V3 Pump 실행 체인과 `tools/vibe3-roblox-platform.mjs` 어댑터를 그대로 사용한다.
- 별도 배포 파이프라인, 우회 스크립트, 쿠키 인증을 만들지 않는다.
- 모바일 입력/UI를 기본으로 설계한다.
- 서버 권한과 클라이언트 표시 로직을 분리한다.
- 저장이 있으면 DataStore 재접속 검증을 통과해야 한다.
- 멀티플레이 기능이 있으면 서버/클라이언트 경계와 Remote 보안 검증을 통과해야 한다.
- `.rbxl`/`.rbxlx` 게시 파일은 검증된 현재 리비전과 같은 게임 폴더 아래에 둔다.
- 실제 게시 성공, 런타임 성공, 독립 QA, 회귀 검증 전에는 출시 성공으로 기록하지 않는다.
- 5개 부서 점수가 낮아도 즉시 폐기하지 않는다. 수정 → 재평가 → 필요 시 HOLD → 재검증 후 구조적 실패 근거가 남을 때만 제외한다.

## 기본 구조

`base/`는 새 Roblox 게임을 시작할 때 복사 기준으로 쓰는 최소 소스다. 게임 규칙·밸런스·저장 키는 포함하지 않는다.
